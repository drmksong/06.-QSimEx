# QSimEx 작업 인계 기록

- 작성일: 2026-09-22
- 프로젝트: `06. QSimEx`
- 기준 기술서: `doc/DesignSpec_20260922.md`

## 1. 최종 목적

시추공에서 산정한 Q'을 이용해 전방 암반을 다음 세 구간으로 판정한다.

```text
Q'_BH >= Q'_upperbound
  -> 확실히 굴착

Q'_lowerbound <= Q'_BH < Q'_upperbound
  -> Q' 단독 판단 금지, 추가 조건 검토

Q'_BH < Q'_lowerbound
  -> 확실히 비굴착 또는 굴착 보류
```

목표는 모든 물리적으로 가능한 암반에 적용되는 임의의 숫자가 아니라, 사전에 검증한 **승인 적용성 범위** 전체에서 사용할 수 있는 보편 상·하한 한 쌍을 제시하는 것이다.

## 2. 오류 정의

양성은 `suitable/good rock`으로 고정한다.

```text
FP / false-safe:
  실제 부적합 암반인데 굴착으로 통과시킴

FN / false-reject:
  실제 적합 암반인데 비굴착 또는 보류하여 좋은 암반을 버림
```

공항 검색대 비유에 대응하는 조건부 위험도도 산출해야 한다.

```text
R_FS_pass  = P(unsuitable face | Q'_BH >= Q'_upperbound)
R_FN_reject = P(suitable face | Q'_BH < Q'_lowerbound)
```

초기 검증 목표는 두 조건부 위험도의 95% 신뢰상한이 각각 5% 이하가 되는 것이다. `alpha_FN`, `alpha_FS`는 최종적으로 사업 안전성 검토와 승인으로 확정한다.

## 3. 검증 시나리오

### Train / Calibration

- 단면 행 단위가 아니라 DFN seed 또는 독립 DFN domain 단위로 7:3 분할
- 예시: 전체 약 480개 단면, Train 약 70%, Validation 약 30%
- 동일 DFN domain에서 나온 단면은 Train과 Validation에 나누지 않음
- Train에서 Q' 후보값을 초기 범위 `1~40`으로 sweep
- 후보별로 FN, FP, `R_FN_reject`, `R_FS_pass`, 95% 신뢰구간, 기대손실, net benefit 계산
- 시각적 변곡점이 아니라 승인된 오류 허용치와 비용 조건으로 두 경계값 결정

```text
Q'_lowerbound:
  FN 위험 95% 신뢰상한이 alpha_FN 이하가 되는 후보 중 가장 높은 값

Q'_upperbound:
  FP 위험 95% 신뢰상한이 alpha_FS 이하가 되는 후보 중 가장 낮은 값
```

- Train 결과가 예를 들어 5.8, 19.2라면 소수점 정리 규칙을 미리 고정
- 정리된 최종 후보값 자체를 Validation에 적용
- 임의의 반올림으로 경계값을 조정하지 않음

### Blind Validation

- Train에서 선택한 상·하한을 재튜닝하지 않음
- Validation에 고정된 경계값을 그대로 적용
- 각 오류율의 점추정치가 아니라 95% 신뢰상한이 5% 이하인지 판정
- 케이스·방향성·밀도별 성능과 최악 조건을 별도 보고
- 통과 결과는 동일 DFN 생성 모델의 신규 seed/domain에 대한 검증으로만 해석
- 실제 현장 전체에 대한 완전한 보증으로 확대하지 않음

## 4. 적용성 원칙

Q' 변동성과 시추공-굴진면 오차는 다음 조건에 민감하다.

- 절리군 수와 상호작용
- P32 및 절리 밀도
- 절리 방향성, Fisher 집중도, 이방성
- 절리 크기 분포와 대형 구조절리
- 시추공·터널 방향과 절리면 교차각
- 층상·평행 절리, 단층·파쇄대
- 터널 형상, 시추공 위치, 관측 윈도우

조건별 연구 결과를 현장 사용자가 직접 선택하지 않는다. 연구 단계에서 넓은 범위를 탐색하고, 승인 적용성 범위의 최악 조건을 통과하는 보편 상·하한을 산출한다.

공통 경계 구간이 존재하지 않거나 특정 조건에서 성능이 붕괴하면 해당 조건은 `판정 불가`로 지정한다.

현장 적용성 질문은 다음 네 가지로 단순화한다.

1. 새로운 대규모 단층·파쇄대 또는 구조절리가 있는가?
2. 주요 절리군이 시추공과 거의 평행하여 절리를 놓칠 가능성이 큰가?
3. 절리 밀도·절리군 수·절리 크기가 검증 범위를 명백히 벗어나는가?
4. 구조·수리·응력 자료와 Q' 사이에 중대한 불일치가 있는가?

```text
모두 아니오
  -> 보편 상·하한 적용

경고 또는 불확실
  -> Q'은 참고값으로만 사용하고 추가 조건 검토

명백한 위험 조건 또는 검증 범위 밖
  -> Q' 단독 판정 불가, 추가 조사 또는 보수적 보류
```

## 5. 현재 구현과의 차이

현재 코드는 단일 threshold 기반의 분류·비용 분석까지 구현되어 있다. 다음 핵심 기능은 아직 없다.

1. DFN seed/domain 단위 Train/Validation 분할
2. `Q'_lowerbound`, `Q'_upperbound` 두 경계값 탐색
3. `R_FS_pass`, `R_FN_reject` 조건부 위험도 계산
4. 95% 신뢰구간 및 bootstrap/계층적 bootstrap
5. Validation에서 고정 경계값을 검증하는 blind report
6. 보편 상·하한을 최악 조건으로 산정하는 로직
7. 네 가지 현장 적용성 질문 기반 판정 게이트
8. `domain_of_applicability` 최종 보고서

현재 구현의 주요 위치:

- threshold·비용 분석: `src/core/decision_test.py`
- 배치 seed 실행: `batch_runner.py`, `multi_batch_runner.py`
- 리포트 생성: `src/core/reporting.py`
- 의사결정 실행/DOA 임시 분석: `multi_case_descision.py`
- 시추공-굴진면 데이터 생성: `src/core/comparison.py`

## 6. 주의할 구현 리스크

### 오류 명칭과 비용 방향

코드에는 다음 명칭이 혼재되어 있다.

- `FN_false_alarm`
- `false_alarm_rate`
- `cost_false_alarm`
- `cost_fp`, `cost_fn`
- `cost_safe`, `cost_alarm`

먼저 FP/FN 의미와 비용 방향을 하나의 표준으로 통일해야 한다. 그렇지 않으면 상·하한 검증 결과의 안전 의미를 해석할 수 없다.

### 기준 라벨

현재 `Qp_face_mean >= 4.0`이 적합 라벨의 예시 기준으로 사용된다. 이 값은 운영 상·하한이 아니며, 독립적인 굴진면 상태·지보 등급·실제 안정성 기준과 연결된 reference label 정책으로 분리해야 한다.

### 현재 DOA 분석의 한계

현재 `domain_of_applicability.csv`는 케이스별 optimal threshold와 net benefit을 사용한다. 이는 최악 조건 기반의 보편 경계값이나 네 가지 현장 적용성 게이트가 아니다.

## 7. 다음 작업 순서

### 1단계: 정의와 테스트 기반 정리

- FP/FN 및 비용 명칭 통일
- 조건부 위험도 수식과 분모 테스트 작성
- reference label과 decision score 분리
- 빈 `src/test` 파일에 핵심 단위 테스트 추가

### 2단계: 검증 데이터 구조

- seed/domain 식별자 보존
- Train/Validation 분할 manifest 생성
- 동일 domain 단면의 세트 혼합 방지
- split 결과와 seed 목록 저장

### 3단계: 경계값 엔진

- Q' 1~40 sweep
- 두 경계값 후보 생성
- Wilson 또는 exact binomial confidence bound 구현
- `R_FS_pass`, `R_FN_reject` 계산
- 상·하한 역전 및 표본 부족 처리

### 4단계: Blind Validation

- Train에서 선택한 경계값 고정
- Validation 결과만 별도 저장
- 조건별·최악 조건 성능 보고
- 95% 신뢰상한 5% 통과 여부 판정

### 5단계: 보편값과 현장 게이트

- 승인 적용성 범위 정의
- 조건군별 결과에서 공통 상·하한 산출
- 공통 구간이 없으면 `판정 불가`
- 네 가지 현장 적용성 질문을 결과 리포트에 포함

## 8. 오늘의 결론

현재 QSimEx는 DFN 생성과 Q/Q' 비교 실험 기반은 갖추고 있다. 그러나 현장 적용 가능한 보편 상·하한을 주장하려면 단일 threshold 최적화에서 벗어나, 오류 정의를 통일하고 독립 seed/domain 검증과 조건부 위험도·신뢰상한을 구현해야 한다.

다음 재개 지점은 **1단계: FP/FN·비용 정의를 통일하고 조건부 위험도 계산을 테스트로 고정하는 작업**이다.
